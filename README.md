# Foreign Job Tracker

Трекер поиска работы за рубежом: очередь компаний, воронка по шагам, режим
выполнения «не думать головой», шаблоны сообщений и полный экспорт данных.

Данные лежат в LocalStorage браузера. Бэкенда нет: перенос между браузерами —
через экспорт и импорт JSON.

## Запуск

```bash
pnpm install     # postinstall сам сгенерирует src/codegen/router/route-tree.gen.ts
pnpm dev         # http://localhost:5173
```

Проверки:

```bash
pnpm lint:typescript
pnpm lint:fix
pnpm build
```

## Стек

React 19 + TypeScript + Vite · TanStack Router (файловые маршруты) · TanStack
Query · Tailwind CSS 4 · Zod · Radix Dialog · lucide-react · sonner.

## Экраны

| Маршрут | Что делает |
| --- | --- |
| `/` | Сегодня: следующее действие, ближайшие задачи, счётчики |
| `/run` | Режим выполнения по всем компаниям — одно действие за раз |
| `/companies` | Список с фильтрами по стране, статусу и поиском |
| `/companies/$companyId` | Обзор: инфо, вакансии, контакты, заметки, история |
| `/companies/$companyId/plan` | Этапы и задачи: статусы, зависимости, свои задачи |
| `/companies/$companyId/run` | Режим выполнения по одной компании |
| `/templates` | Шаблоны RU/EN с подстановкой плейсхолдеров |
| `/settings` | Профиль, ритм, экспорт/импорт JSON, импорт CSV |

## Как устроена воронка

Определения шагов — в коде (`src/lib/pipeline/constants/uae-flow.ts`).
В LocalStorage лежат только экземпляры задач: что сделано, что отвечено, какие
даты. Правка воронки меняет логику, а не данные.

Движок — чистая функция `applyOutcome(...)`: принимает шаг, выбранный исход и
текущее состояние, возвращает патч (какие задачи закрыть, какие создать, что
сделать со статусом компании и контактами). Записывает патч уже слой
`src/actions/pipeline`.

Начальные шаги: `triage → audience → recon → {apply, connect_engineer,
connect_hiring}`. Остальные (`follow_up_1`, `follow_up_2`, `full_message`,
`screening_prep`, `thank_you_letter`, `proof_of_work`, `revive`) создаются
эффектами по мере необходимости.

## Замена LocalStorage на API

Всё хранение изолировано в `src/lib/storage`:

- `drivers/local-storage-driver.ts` — единственное место, которое знает про
  `localStorage`;
- `utils/create-collection-repository.ts` — универсальный CRUD-репозиторий,
  все методы асинхронные и по форме повторяют REST-ответы;
- `repositories/index.ts` — репозитории по сущностям.

`src/actions/**` — это TanStack Query поверх репозиториев. Переезд на бэкенд =
переписать `repositories/*` на `fetch`; actions, widgets и entrypoints не
трогаются. Прямое обращение к `localStorage` вне `lib/storage` запрещено
правилом ESLint.

## Импорт и экспорт

- Экспорт: `foreign-job-YYYY-MM-DD.json` — компании, контакты, вакансии,
  заметки, задачи с ответами, история, шаблоны, настройки.
- Импорт JSON: стратегия `merge` (по `id`, свежее выигрывает) или `replace`.
- Импорт CSV: колонки `Компания, Очередь, Уровень, Информация, Статус,
  Дата контакта, Следующий контакт, Нанимающий(е), Инженер(ы)`.
  Дедупликация по названию компании.

## Чего пока нет

- Бэкенда и синхронизации между устройствами (только экспорт/импорт).
- TanStack Form: формы v1 простые и живут на локальном состоянии в хуках
  виджетов. При росте форм переводить на `useAppForm`, как в genario-frontend.
- Фильтры списка компаний хранятся в состоянии, а не в search params.
- Тестов нет.
