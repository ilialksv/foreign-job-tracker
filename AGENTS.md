# AGENTS.md — Foreign Job Tracker

Канонический рабочий контракт для агентов в этом репозитории. Архитектура
скопирована с `genario-frontend`; при расхождении документации и кода верить
коду и обновлять документацию в том же изменении.

## Снимок проекта

- React 19 + TypeScript, сборка Vite.
- Пакетный менеджер: `pnpm`.
- Маршрутизация: файловые маршруты TanStack Router в `src/routes`.
- Состояние: TanStack Query поверх репозиториев `src/lib/storage`.
- Стили: Tailwind CSS 4, `cn()` из `@/shared/utils/cn`.
- Валидация: `z` из `@/lib/zod`, не прямой импорт `zod`.
- Бэкенда, кодогенерации API, i18n, auth и Sentry нет.

## Слои

| Путь | Назначение |
| --- | --- |
| `src/routes` | Объявления маршрутов, параметры, guard-логика |
| `src/entrypoints` | Композиция страниц |
| `src/widgets/<domain>` | Сложные доменные блоки: UI + поведение |
| `src/features/<domain>` | Переиспользуемый презентационный доменный UI |
| `src/actions/<domain>` | Хуки поверх репозиториев: queries и mutations |
| `src/shared` | Кросс-доменные UI-примитивы, хуки, утилиты, константы, типы |
| `src/lib` | Инфраструктура: storage, pipeline, tanstack-*, zod |
| `src/codegen` | Сгенерированные файлы, не редактировать руками |

Направление зависимостей:

```text
routes -> entrypoints -> widgets -> features/actions -> shared/lib
```

## Правила хранения данных

- Прямое обращение к `localStorage` вне `src/lib/storage` запрещено (правило
  ESLint `no-restricted-globals`).
- Новая сущность: тип в `src/shared/types/entities.ts`, ключ в
  `lib/storage/constants/storage-keys.ts`, репозиторий в
  `lib/storage/repositories/index.ts`, хуки в `src/actions/<domain>/hooks`.
- Все методы репозиториев асинхронные — это контракт на будущий API.
- Любая новая коллекция добавляется в `createDatabaseSnapshot` и
  `restoreDatabaseSnapshot`, иначе экспорт станет неполным.

## Правила воронки

- Определения шагов — только в `lib/pipeline/constants/uae-flow.ts`.
- `lib/pipeline` не знает про хранилище: функции принимают состояние и
  возвращают патч.
- Побочные эффекты (запись, инвалидация кэша) — в `src/actions/pipeline`.
- Статус компании вычисляется `resolveCompanyStatus`; терминальные статусы
  вручную не пересчитываются.

## React и хуки

- Компоненты преимущественно рендерят. Логика — в колокейтед-хуке с именем по
  компоненту (`CompanyPlan` → `useCompanyPlan`).
- `useMemo` для производных коллекций и ветвлений рендера, `useCallback` для
  обработчиков.
- Инлайн-функции и инлайн-тернарники в JSX не использовать; исключение —
  `className` с объектным синтаксисом `cn()`.
- Значение, вычисляемое условием, сначала называется переменной, потом
  передаётся в проп.
- `useEffect` — только для синхронизации с внешними системами. Сброс формы
  делается размонтированием (условный рендер), а не эффектом.
- Файл компонента содержит главный компонент плюс его скелетоны и заглушки;
  значимые дочерние компоненты выносятся в отдельные файлы.
- Утилиты, константы и типы не живут в файлах компонентов и хуков.
- Приведения типов (`as`) избегать; вместо этого явные аннотации и guard-и.
  `satisfies` не используется.
- Параметры функций, хуков и компонентов передаются одним объектом.

## Формы

Все формы — на TanStack Form через `useAppForm` из `@/lib/tanstack-form`.
Локальное состояние под значения полей не заводить.

Структура формы внутри виджета:

```text
schemas/<name>-form-schema.ts     Zod-схема + тип значений + дефолты
utils/<name>-form-helpers.ts      валидаторы из схемы
utils/prepare-<name>-form-values.ts   сущность -> значения формы
utils/prepare-<name>-submit-data.ts   значения формы -> данные репозитория
hooks/use-<name>-form.ts          useAppForm, мутации, onSubmit
components/<name>-form.tsx        <form> + кнопки
components/<name>-form-fields.tsx withForm, поля (от трёх полей и больше)
```

Правила:

- Валидаторы собираются из Zod-схемы через `createFormValidateFn`; для форм
  редактирования на `onSubmit` идёт `createFormMatchValidateFn`, чтобы нельзя
  было сохранить неизменённые значения.
- Общие кирпичики схем — в `@/lib/zod/schemas/common`
  (`requiredTextSchema`, `optionalUrlSchema`, `numericTextSchema`,
  `requiredEnumSchema`, `optionalDateSchema`). Не дублировать тексты ошибок.
- Поля рендерятся только компонентами поля: `field.InputField`,
  `field.TextareaField`, `field.SelectField`, `field.CheckboxField`. Ошибку
  показывает `FieldLayout` внутри них, руками ошибки не выводить.
- Кнопка отправки — `form.SubmitButton` внутри `form.AppForm`, чтобы работал
  `canSubmit`. Для формы в диалоге кнопка живёт в футере и получает
  `form={formId}`.
- После успешного обновления вызывать `formApi.reset(value)`, после создания —
  `formApi.reset()`.
- У `<form>` всегда `noValidate`: валидация наша, а не браузерная.
- Форма шага воронки собирается из определения шага: типы полей берутся из
  `StepField.type`, обязательность — из `StepField.required` и
  `StepOption.requiredFields`. Добавлять новое поле шага нужно в
  `lib/pipeline/constants/uae-flow.ts`, форма подхватит его сама.

## Дизайн

- Цвета, типографика, радиусы и тени живут токенами в `src/styles/globals.css`
  и пробрасываются в Tailwind через `@theme inline`. Хардкод цвета в классе —
  ошибка: берём токен (`bg-surface`, `text-ink-2`, `border-line`).
- Три шрифтовые роли: `font-display` (Golos Text) для заголовков, `font-sans`
  (IBM Plex Sans) для текста, `font-mono` (IBM Plex Mono) для дат, счётчиков,
  надзаголовков и служебных подписей. Цифры в колонках — `tabular-nums`.
- Содержимое живёт на белой поверхности, а не прямо на бумаге: `Section`
  сам заворачивает заголовок и детей в общую `Card`. Заголовок не висит над
  блоком — он часть блока. `surface={false}` оставлено для редких случаев,
  когда внутри своя поверхность.
- На бумаге лежит только зона шапки страницы: `PageHeader`, панель фильтров и
  сводка. Всё остальное — в блоках. `Panel` с тенью на экране одна.
- Линии экономим. Заголовок секции не подчёркивается; горизонтальная линия
  разделяет только однотипные строки списка (`last:border-b-0`) и структурные
  зоны — табы, шапку и футер диалога. Вложенные формы и подсказки выделяем
  фоном `bg-surface-2`, а не рамкой.
- Семантика статусов (`accent` / `warn` / `ok` / `stop`) отделена от акцента и
  живёт в `badge-variants`; точка `StatusDot` — основной носитель статуса в
  списках, бейдж — там, где нужно слово.
- Переключатель вкладок — сегментированный контрол: выбранная вкладка
  отличается сразу поверхностью, рамкой и цветом текста (одного тонкого
  подчёркивания мало), и стоит вплотную к содержимому без разделяющей линии.
- Шапка сущности (имя, мета, статус, действия) живёт в лейауте над
  переключателем вкладок, а не внутри одной из вкладок.
- Единая шкала высот у всех контролов: sm 32, md 36, lg 44; иконочные кнопки
  повторяют её (`icon-sm` 32, `icon` 36). В одном ряду размеры совпадают.
- Белые блоки все одинаковые: рамка `border-line`, без тени. Тень остаётся
  только у диалога.
- Не подставляем декоративные надзаголовки и подписи, если рядом уже есть
  заголовок, описание или подпись кнопки.
- Списки — плотные строки с волосяными разделителями, а не сетка карточек.
  Действия в строке появляются на hover и не мешают клику по самой строке.

## Шаблоны

Один шаблон хранит оба языка (`bodies.ru` и `bodies.en`), переключение
происходит внутри шаблона. Старая схема с отдельным шаблоном на язык
подтягивается миграцией `migrateTemplates` при чтении коллекции.

## Режим выполнения

- Доступность шага считается, а не хранится: `getTaskMode` возвращает
  `active`, `completed` или `blocked` на основе статуса и незакрытых
  зависимостей. Заблокированный шаг нельзя выбрать в навигаторе.
- Закрытый шаг открывается на правку ответов (`useUpdateTaskAnswers`) без
  повторного применения эффектов. Чтобы переиграть исход, шаг возвращается в
  работу через `useReopenTask`; откат эффектов прошлого исхода не делается.
- У шага компании свой маршрут `/companies/$companyId/plan/$taskId`: список
  этапов и страница этапа, отдельной страницы «выполнение» нет.
- Элемент списка открывается кликом по самой строке (`TaskRow` принимает
  `renderContent` и оборачивает содержимое ссылкой). Отдельных кнопок
  «Открыть» не заводить; кнопками остаются только действия над элементом.
